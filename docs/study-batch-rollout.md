# Лекции и пакетные задания: безопасное включение

Текущее состояние: код сервера разработан и проверяется локально, production не изменён. Для /api/v1/ai/lectures и /api/v1/ai/answers требуется отдельное согласие владельца. Существующие quizzes/flashcards/review/extract остаются совместимыми. Android показывает недоступность новых функций до проверки capabilities через авторизованный GET status; ни отсутствие маршрута, ни сохранённый план не являются успешной генерацией.

## Перед разрешённым production-этапом

1. Проверить diff 0a5651f к действующей версии; сохранить идентификатор действующего Worker deployment и доступный исходник для отката. Не выводить/не менять secrets.
2. Использовать существующий testhelper-ai и текущие bindings SQLite AiQuota, migrations, Firebase project и модель; не создавать Worker/SQLite/Firebase заново. Бесплатный тариф и квоты остаются: пользователь3/мин20/сутки, IP10/мин60/сутки, глобально200/сутки. Не запускать миграции данных ради этих маршрутов.
3. node --test backend/cloudflare/tests/security.test.mjs backend/cloudflare/tests/study.test.mjs. Проверить JWT/verified email/Google/password, запрет legacy admin для новых маршрутов, лимиты JSON и неполные ответы. Тесты используют синтетические данные; они не измеряют качество Gemini.
4. Только после отдельного разрешения — штатный deploy существующим локальным Wrangler. Повторно проверить конфигурацию и бесплатный тариф, не добавлять зависимости/секреты/платёжные аккаунты.
5. С согласия на тестовые запросы — авторизованный status, одна небольшая лекция и одна группа исходных вопросов с двумя/неизвестными ответами. Проверить точные ID, маркировку CLOUD_AI/UNKNOWN, квоты и офлайн-чтение. Не выводить JWT и учебный текст в логи. Запросы учитываются в действующей квоте.
6. При проблеме вернуть прежний deployment штатным rollback без удаления SQLite/секретов. Записать идентификаторы и реальные результаты; не объявлять новую интеграцию работающей до этих проверок.

## Поведение Android

- Последовательная отправка с интервалом не менее22с и сохранением следующего времени на диске. 500 вопросов обычно требуют20 запросов, то есть всей свободной дневной квоты; текст/JSON могут увеличить число частей. План и его отправляемый текст проверяются до согласия. Смена источника/назначения создаёт новый план и требует нового согласия.
- Выполненные партии сохраняются атомарно. Пауза, отмена и частичный результат доступны. 429 останавливает серию до ручного продолжения. Потеря ответа/409/502/503/тайм-аут не вызывают автоматических повторов: требуется отдельное разрешение на один новый запрос с предупреждением о возможном повторном расходе квоты.
- Native foreground service запускается пользователем с уведомлением. Compose только показывает состояние. Данные аккаунтов изолированы; смена UID отменяет работу. После force-stop/системного завершения нужен ручной вход в задачи; незавершённый HTTP имеет неопределённый исход.
- На Android35+ dataSync имеет системный лимит длительности; Android16 WorkManager также расходует JobScheduler quota, поэтому новый WorkManager не установлен. Выбран прямой service с обработкой onTimeout и ограниченным wake lock. Не обещаем продолжения сети при любых настройках энергосбережения.
- Нажатие уведомления открывает приложение, затем набор → «Задания». Нажатие паузы во время отправки может оставить неопределённый исход, а не гарантированно отменить уже выполненный сервером запрос.
- Частичная лекция маркируется частичной. Пользовательские правки сохранённой лекции не перезаписываются при поступлении новых частей: полные ответы остаются в задании, автоматическое слияние с отредактированным текстом не выполняется.

Официальные ограничения Android: https://developer.android.com/develop/background-work/background-tasks/persistent/how-to/long-running и https://developer.android.com/develop/background-work/services/fgs/timeout .
