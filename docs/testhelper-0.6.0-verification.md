# TestHelper 0.6.0 Beta — итог проверки

Дата: 22.11.2026. Ветка feature/android-mvp. Исходники APK: 98fb0e39decbc098b6c3522de32bf945219b939f (итоговый отчёт — отдельный коммит). Основной пользовательский запрос выполнен по шести этапам. Все 16 изображений ZIP просмотрены как UX-референсы; чужие иллюстрации в приложение не копировались.

## Реальные изменения

- Единая почти белая/голубая дизайн-система на существующих компонентах, собственный знак, компактная авторизация, официальная Google-кнопка; тёмная/системная темы сохранены.
- Главная показывает настоящие наборы, поиск, количества и историю. В наборе четыре раздела: Материал, Тест, Карточки, Подготовка. Реально работают переименование, архив с восстановлением и экспорт ZIP выбранного набора.
- TXT/DOCX/PDF/JSON/фото прикрепляются отдельными документами: название, формат, размер, статус, открытие и открепление. Оригинал и полный извлечённый текст хранятся локально внутри аккаунта, не вставляются в ручное поле. Есть текстовый просмотр, нативный просмотр PDF/фото с увеличением, отдельные заметки, открытие готовых вопросов без Gemini.
- Устранён локальный предел 12 000 символов для вложенного материала. Границы: оригинал 64 МиБ, текст 8 млн символов и существующие ограничения парсеров. Предпросмотр страниц не обрезает сохранённый документ. Черновик сохраняет выбранный источник, часть, настройки и страницу просмотра.
- Gemini получает только выбранный фрагмент после отдельного подтверждения одного запроса. Сохраняются точное покрытие исходного текста и границы распознанных вопросов; слишком большой/неоднозначный блок требует ручного диапазона. Лимиты прежнего API (12 000 символов материала, 65 536 UTF-8 байт запроса) не повышались. Автоматических цепочек нет. Успешные части считаются отдельно для текущих настроек; это не подтверждение правильности AI-ответов.
- Результаты показывают все вопросы, выбранные ответы, подтверждённые ключи/неподтверждённые предположения, фильтр ошибок и повтор ошибок. Мультивыбор оценивается точным совпадением; неизвестные/предполагаемые ключи не входят в строгую оценку.
- У карточек есть переворот, реальные сохранённые оценки, прогресс занятия и завершение. Ошибка записи не продвигает занятие. Загрузка показывает этапы/отмену; повреждённые банки перечисляются без удаления/перезаписи файлов.
- Большие тесты и активные ответы записываются в фоне. Поколение записи и проверка отмены не позволяют старому снимку вернуть закрытую попытку. Библиотека прежних форматов остаётся доступной без миграционной перезаписи.

Основные файлы: MaterialStore.kt, MaterialSlices.kt, MaterialUiModel.kt, AiScreen.kt, QuizRepository.kt, StudySetStore.kt, StudySetHome.kt, StudySetWorkspace.kt, StudySetExport.kt, MaterialViewer.kt, DocumentPreview.kt, AuthEntryScreen.kt, StudySessionScreens.kt, ActiveAttemptStore.kt; общие SteamTheme/SteamComponents/StudyScreens и новые регрессионные тесты.

## Что фактически запускалось

Полная команда из корня:

```powershell
& .\android\.build-tools\run-checks.ps1 -Tasks '-Pkotlin.compiler.execution.strategy=in-process',':app:testDebugUnitTest',':app:lintDebug',':app:assembleDebug'
```

Итог: BUILD SUCCESSFUL, 2m 55s, 90 actionable tasks (30 executed, 60 up-to-date). Полный набор: **153 теста, 0 failures, 0 errors, 0 skipped**. Перед ним проходили целевые наборы этапов: 12, 17, 21, 26 и 31 тест (с пересечением, не суммировать). Первый полный прогон нашёл устаревшее ожидание system для новой установки: тест обновлён на light, сохранена отдельная проверка старых настроек system/dark.

Автоматически проверены парсеры TXT/DOCX/JSON, кодировки, многострочность/варианты/ключи, масштаб 800/1500 вопросов, мультивыбор и достоверность ключей; сохранение/отмена/целостность полного материала >12 000 символов; точное покрытие/границы частей/Unicode/лимиты API; восстановление черновика; read-only совместимость прежних наборов и изоляция UID; архив/экспорт без соседних данных/секретов; результаты/карточки/отменённые снимки; mock-сценарии авторизации и контраст light/dark. OCR/PDF pipeline тестируется с контролируемыми адаптерами: это не запуск нативного распознавания на Android.

Эти файлы не отправляются в Git.

Backend/production в этой задаче не менялись, серверные тесты и live-генерация повторно не запускались. Работа ранее проверенного пути Firebase → Cloudflare → Gemini сохраняется архитектурно; новый Android UI надо проверить на телефоне.
